# Security policy

## Supported versions

Security fixes are provided for the latest published version.

## Reporting a vulnerability

Use **Security → Report a vulnerability** in the GitHub repository so the
report is private. The repository owner should enable GitHub Private
Vulnerability Reporting before the first public release.

If that entry is unavailable, open a minimal public issue asking for a private
contact channel. Do not include exploit details or sensitive data in the issue.

Never attach real access tokens, refresh tokens, app secrets, tenant keys,
customer identifiers, or lark-cli profile files. Use synthetic placeholders and
include the package version, operating system, Node.js version, and the smallest
reproduction possible.
